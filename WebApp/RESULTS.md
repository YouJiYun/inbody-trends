## 本轮有效改进

评分：标题与控制标题之间的候选框排除贯穿全高的纸边/线条，
按局部背景强度提取浅色大字分子，排除小字 `/100`。
只有唯一的两到三字形分子及两次可靠数值复核才保存；
同字号竞争分子不猜选。两张实际评分已正确保存。

人体成分：保持五行单位列、参考区间边界和结果列定位；
原格无法可靠确认时，用连通字形分组排除边线，切更小数值块，
按局部背景二值化后做两种缩放的实际 OCR。
词置信度、精度、范围、一致性要求不降；
原格仍能辨认出的数值字符与小块结果冲突时拒绝，不用强置信多数覆盖冲突。
新增 A 无机盐及 B 蛋白质；两张五格均可信 4/5。

上一版有效的日期双裁图、核心单词分割、刻度/结果框分离继续保留。
没有反推水分、按样例数值/文件名录入、真实裁字训练、日期猜算或改 oracle。

水分剩余问题属于字符识别/可靠复核，而不是没找到行或栏：
A 原格数值读法与紧裁的读法冲突，不能按高置信小块直接覆盖；
B 原格有数值，但紧裁漏字符或读成字母，未通过范围/词置信度/一致性检查。
逐字符本地实验在 A 的二值化诊断裁图上正确，
但 B 的一个数字在原灰度与二值化之间不一致；
从完整原图到入库的集成实测仍为 18/20，没有可靠新增收益，所以没有保留。
同一模型多次识别可能相关误读，不能用一次高置信或单裁图成功保证正确。
本轮有界验证到此停止，保留零错的最佳版本，不继续同方案循环或放宽守卫。

`Delivery\pwa-coverage-manifest.json`。旧 final/accuracy 包保持不变，

解包源码根目录，Node.js 22 或更新版本执行：

```powershell
node .\WebApp\tools\serve.mjs
```

电脑打开 `http://127.0.0.1:8787/`，已含构建资源，无需先 npm 安装。
重建时进入 `WebApp`，执行 `npm ci --ignore-scripts --no-audit --no-fund`、
`npm test`、`npm run build`；`npm run test:browser` 需要本机 Edge。
初次完整缓存约 33.5 MiB 后才可离线 OCR；直接双击 HTML 不支持完整功能。
回环服务器没有上传接口；浏览器存储可能被回收，备份含未加密健康资料，
请手动保存在私密「文件」或 iCloud Drive，不是自动云同步。

`127.0.0.1` 指当前电脑，不是手机入口。
手机需另获批准的 HTTPS 静态托管，再用 Safari「分享 → 添加到主屏幕」。
所附标准 Ubuntu 手动 Pages workflow 仅是方案；
须重新批准本轮新增源码/模型/许可/配置及 Pages 设置后才能上传。
