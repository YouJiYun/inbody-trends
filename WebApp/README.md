# 身体记录 PWA（本地原型）

原生 SwiftUI 工程保持不变。本目录是独立、中文、移动优先的静态 PWA。
**两张真实照片的自动提取尚未达标，不能作为已可用的全自动报告扫描器交付。**
本地界面、存储、备份和离线识别管线已实现；合成报告识别成功不代表真实照片成功。
模板局部识别已使两张原图的完整日期和五个核心指标自动保存，
并保存评分、蛋白质和无机盐。
固定 20 项人工标注对照中，正确候选及正确入库均为 18 项（90%），
实测错误入库为 0；上一版本正确入库 14 项。
两张的水分仍未可靠识别，20/20 的有限目标尚未达到，不能保证普适 100%。
历史没有可靠挽救。这两张是开发样例，不是独立泛化测试。
这不是全报告或字符准确率，不应把候选与正确入库混为一谈。

## 本地运行

需要 Node.js 22 或更新版本。已在 Windows、Node 26、Microsoft Edge 验证。

```powershell
Set-Location .\WebApp
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run build
npm start
```

在电脑打开 `http://127.0.0.1:8787/`。服务只绑定本机，不提供照片上传接口。
另一个终端在本目录运行 `npm run test:browser`，使用已安装的 Edge。
测试截图只使用明确标记的合成演示，写入 `artifacts`。

## 已实现

### 已保存照片恢复

在「报告」打开已有报告，点「使用已存原图重新识别」，不需重拍、重新传图或清理网站数据。
日期及报告身份可靠时，成分表/评分独立核实的至少两项可标记为「部分保存」；
缺失、可信矛盾及仅有不稳定单处候选的字段不入趋势。
可信日期无法确认时仍仅保留原图。重试失败不删除旧数据；同图日期/值矛盾不覆盖，
兼容旧 IndexedDB 和版本 1 备份，可从部分记录升级为核心完整记录，且不降低旧值置信度。
设置中的「检查并加载应用更新」只更新资源，不清空照片/记录。

- 相机/相册文件输入，本机 Tesseract.js WASM 中文、英文 OCR。
- 纸张校正、阴影处理、空间分区、单位、日期、小数与一致性检查。
- 全页解析失败时，使用非个人的黑条版式及网格或评分/控制标题定位，
  在本机切字段小块复核；新增人体成分结果列、评分分子框、最右历史网格独立复核。
  孤立数字使用单词分割及两种缩放复核；大字号结果框与小刻度分离，
  日期定位仅提供位置，两次可信日期裁图需一致，可信来源冲突仍拒绝。
  评分分子排除贯穿整框的纸边/线条，并按局部背景检测浅色数字；
  人体成分小数字增加字形分组、局部二值化及两种缩放复核，
  与原格中实际数值字符不一致时仍拒绝，不以多数投票抹掉冲突。
  只有可靠且一致的字段参与保存；网格、时间或冲突拒绝不会放宽入库规则。
- 核心数据不完整时保存原图为待识别，不进趋势、不要求手填数字。
- 已保存图片防重；待识别图片允许重试；完整报告优先于历史摘要。
- 所有实际识别指标的测量时间排序、时间窗口、单点状态与原图来源。
- IndexedDB 保存照片和记录，按应用路径隔离；删除来源后重建其贡献的趋势。
- 含原图的 JSON 备份，照片摘要、结构、日期和来源一致性校验后原子合并。
  校验失败或写入配额不足时不会先清空原库。
- 自托管模型和应用资源约 33.4 MiB；首次联网下载，完整缓存后可离线 OCR。
  缓存只包含静态资源，不保存照片、备份或识别文本。

模型、代码和许可证通过静态网站下载；照片不发送至 OCR 服务。
没有账户、广告、遥测、远端字体或自动云同步。
浏览器存储可能被回收，清理网站数据或换手机可能丢失记录。
备份未加密，含健康资料；请手动保存到私密的「文件」或 iCloud Drive。
持久存储申请是尽力而为，不是永久保证。
单张照片上限 25 MiB、40 MP；备份上限 150 MiB。
HEIF/AVIF 能否导入取决于浏览器解码支持；不支持时会明确报错。

## 验证范围与限制

16 项 Node 领域/模板几何测试和 11 组实际 Edge 浏览器检查通过。
浏览器检查包括真正的合成 PNG OCR 自动保存、重复导入、待识别重试、
来源删除、原子恢复、损坏文件拒绝、模拟配额失败回滚、离线新 worker OCR、
空白图片拒绝和 390 × 844 视口。
新增合成裁图检查验证实际数字和时间 OCR，排除小刻度并拒绝同字号双数值体重。
三种字体及独立日期的实际图片测试中，Arial/Georgia 核心完整；
Times New Roman 的 BMI 仍漏读并安全拒绝整张，非法日历日期也拒绝。
不能将安全拒绝描述为整张合成模板识别成功。
新增真正的合成人体成分/评分裁图 OCR，以及独立位置脂肪冲突拒绝检查。
评分新增浅色数字、全高灰边、小字分母及同字号竞争分子的真实图片回归。
交付包的最新原图实测见本目录 `RESULTS.md`；开发目录见上级 `Review\PWA最终实测与交付.md`。
`Review\PWA实测说明.md` 保留原始 0/20 基线。不能用 OCR 置信度推算准确率。

没有 iPhone Safari 真机、实际相机或长期存储回收验证。
分段、阻抗与报告内历史只在明确布局/标签/单位时提取，真实覆盖尚未建立；
不承诺所有 InBody 型号或所有字段。
人体成分是设备估计值，应用不提供医疗诊断或处方。

## 后续部署需单独批准

当前只在本地。此前原生候选的批准不包括本 PWA。
旧的 20 文件 PWA 候选保持不变，不包含本轮更新；公开前必须重新整理审查并获得批准。
最新源码交付包包含已构建的 `dist`，无需先装 npm 依赖即可用 Node 运行
`node .\WebApp\tools\serve.mjs`（从解包根目录执行）。直接双击 HTML 不支持 worker/离线安装。
审核候选只含独立合成测试与静态源代码，排除所有私人输入、标注和日志。
批准新增内容和 Pages 设置后，可通过标准 Ubuntu runner 构建并部署静态资源，
不需要付费后端、iOS 签名或 larger runner。
HTTPS 发布后才能在 iPhone Safari「分享 → 添加到主屏幕」。
在真实照片提取问题解决前，不建议作为正式自动扫描产品上线。
