# 身体记录：设计与研究

这是原生 SwiftUI iOS 应用的设计方向，HTML 仅为视觉预览，不是 iOS 模拟器或 OCR 演示。预览数字是合成数据，首次运行真实应用为空。

## 设计

- 概览：最近一次测量、体重/骨骼肌/体脂率、与前次差异；不使用“越低越好”的奖励颜色。
- 扫描：系统文档相机与照片选择器，本地 Apple Vision 中文识别；可靠结果自动保存，失败提示重拍，禁止手填或猜值。
- 趋势：任何实际保存指标均可进入详情，按测量时间排序，支持时间窗口与来源；不把缺失数据画为零。
- 报告：原图追溯、完整指标、识别质量、导出与删除。报告内历史明确标注为部分数据。
- 暖白背景、青绿强调色、系统字体、卡片；原生实现支持深色模式、Dynamic Type 和 VoiceOver。预览是布局意向，真实界面遵循系统导航和控件。

## 潜在需求与边界

1. 测量时间不是上传时间：使用报告时间，不用“今天”兜底；无可靠时间需重拍。
2. 重复与冲突：同次测量合并，完整报告优先；冲突不能覆盖可靠数据。
3. 扫描质量：多列内容、参考区间、图表刻度和历史栏可能干扰识别。需要 bounding boxes、分区与交叉校验，不能只串接 OCR 文本。
4. 历史补齐：底部历史只可能补齐体重、骨骼肌和体脂率，不能反推 BMI 或脂肪重量；日期不清晰则跳过并说明。
5. 隐私：不建立账号，不使用云 API，不存识别到的姓名/电话/报告 ID。原图可能含个人信息，因此本地文件需要保护与备份排除；导出前明确提示。
6. 测量条件：提示尽量同一时间、状态与设备比较，不做医学诊断、减重处方或个人风险评级。

## 官方依据

- [Apple Vision](https://developer.apple.com/documentation/vision)：图像文字识别可在设备内执行。
- [定位并显示识别文字](https://developer.apple.com/documentation/vision/locating-and-displaying-recognized-text)：识别结果含位置，支持空间解析。
- [InBody 测试说明](https://inbodyusa.com/general/inbody-test/)：一致的测量条件有助于可比性，时间、饮水和运动等影响结果，常见测量间隔为 2–4 周。

## 合成测试与验证边界

公开的界面和测试使用独立合成数据，不含任何个人报告。合成图片模拟左列主分析、右列评分与控制、参考区间、小字图表刻度和多列干扰。左右肢体必须依据报告的左右标记与阻抗表头，不能根据人体朝向猜测。

当前 Windows 无 Xcode、iOS 模拟器或 Apple Vision 运行环境。原生 OCR、系统相机与 SwiftUI 验证必须在 macOS/Xcode 执行；本地文本或工程结构校验不能替代它们。合成图片测试可由手动触发的标准 GitHub macOS runner 执行，但本轮尚未运行。
